# Duskey

Каталог цифровых товаров (аффилиат-витрина на GGSel) + собственный модуль
пополнения Steam с реальной оплатой через **Antilopay API**.

## Структура проекта

```
api/index.js          — точка входа для Vercel (экспортирует Express-приложение)
app.js                 — само Express-приложение (роуты, статика)
server.js              — запуск локального сервера (node server.js)
lib/antilopay.js        — подпись/проверка запросов и клиент Antilopay API
lib/store.js            — хранилище заказов (Upstash Redis в проде, /tmp локально)
routes/steamTopup.js     — проверка Steam-аккаунта, создание пополнения, статус
routes/antilopayWebhook.js — приём и проверка подписи Callback от Antilopay
public/index.html        — витрина (бывший catalog-v12.html), раздаётся как статика
```

## Как это работает

- Каталог (`public/index.html`) — статичная витрина. Все карточки, кроме
  «Пополнение Steam», ведут на GGSel по партнёрской ссылке, как и раньше.
- Виджет «Пополнение Steam» теперь **не** уходит на сторону — он вызывает
  `POST /steam/check-account`, потом `POST /steam/create` на этом же сервере,
  которые обращаются к Antilopay API (`lib/antilopay.js`), создают платёж и
  возвращают `payment_url`, куда пользователь и переадресуется.
- После оплаты Antilopay шлёт Callback на `POST /antilopay-webhook` —
  подпись проверяется публичным ключом (`ANTILOPAY_PUBLIC_KEY`), статус
  заказа обновляется в хранилище.
- Страницы `GET /steam/success` и `GET /steam/fail` — куда Antilopay
  редиректит пользователя после оплаты.

## Локальный запуск

```bash
npm install
cp .env.example .env      # заполните ключи (см. ниже)
npm run dev                # http://localhost:3000
```

Без реальных `ANTILOPAY_*` ключей сайт откроется и будет работать, но
кнопка «Купить» в виджете Steam вернёт ошибку — это ожидаемо.

## Деплой на Vercel

1. Залейте проект в git-репозиторий, импортируйте его в Vercel
   (vercel.com → Add New → Project).
2. Vercel сам подхватит `vercel.json` — весь трафик идёт в
   `api/index.js`, где живёт Express-приложение целиком (статика,
   API, вебхук).
3. В Project Settings → Environment Variables добавьте все переменные из
   `.env.example`, как минимум:
   - `SITE_URL` — итоговый домен проекта (важно для `success_url`/`fail_url`)
   - `ANTILOPAY_PROJECT_ID`, `ANTILOPAY_SECRET_ID`, `ANTILOPAY_PRIVATE_KEY`,
     `ANTILOPAY_PUBLIC_KEY` — из личного кабинета Antilopay
4. **Хранилище заказов.** На Vercel нет постоянной файловой системы — без
   внешнего хранилища заказы будут теряться между вызовами функции.
   Подключите Redis: Project → Storage → Marketplace Database Providers →
   **Redis** (Upstash) → Connect. Vercel сам пропишет переменные вида
   `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` (или старые
   `KV_REST_API_URL`/`TOKEN`, если у вас уже был подключён Vercel KV раньше
   — `lib/store.js` понимает оба варианта). Без этого шага проект всё
   равно задеплоится и заработает, но проверка статуса заказа
   (`GET /steam/status/:order_id`) не будет надёжной.
5. Задеплойте (`git push` или кнопка Deploy).
6. В личном кабинете Antilopay, в настройках вашего Проекта, укажите адрес
   приёма Callback: `https://<ваш-домен>/antilopay-webhook`.
7. Проверьте `https://<ваш-домен>/health` — должно вернуть
   `"storage":"upstash-redis"` (если Redis подключён) и открыться сама
   витрина на `/`.

## ⚠️ Юридические тексты — обязательно проверьте перед публикацией

В `public/index.html` есть три юридических документа (публичная оферта,
политика конфиденциальности, возврат и обмен), которые изначально были
написаны для сайта-каталога, **не принимающего оплату вообще** («Duskey не
принимает оплату… всё это пользователь указывает на стороне GGSel»). Я
добавил в них разделы-исключения для нового раздела «Пополнение Steam»
(где деньги и данные — логин Steam, email — реально обрабатываются этим
сайтом через Antilopay), но это черновая правка, а не готовый юридический
текст:

- в оферте, п. 2.1 стоит `[TODO: заменить на реальные реквизиты продавца]`
  — нужно вписать реальные данные продавца услуги пополнения (ИП/самозанятый/ООО);
- стоит свериться с требованиями 152-ФЗ по обработке персональных данных
  (email, IP) и, при необходимости, с юристом — особенно если планируете
  принимать банковские карты.

До этой правки видимая пользователю политика конфиденциальности прямо
утверждала, что сайт не собирает email и логины — с реальной оплатой
через Antilopay это уже не так, и стоило поправить, прежде чем пускать
на сайт живой трафик и деньги.

## Полезные эндпоинты

| Метод | Путь                          | Назначение                                  |
|-------|-------------------------------|----------------------------------------------|
| GET   | `/health`                     | статус сервиса и хранилища                    |
| POST  | `/steam/check-account`        | проверка Steam-логина                         |
| POST  | `/steam/create`                | создание платежа на пополнение                |
| GET   | `/steam/status/:order_id`      | статус заказа (для поллинга)                  |
| POST  | `/antilopay-webhook`           | приём Callback от Antilopay                   |
| GET   | `/steam/success` / `/steam/fail` | редирект-страницы после оплаты              |
