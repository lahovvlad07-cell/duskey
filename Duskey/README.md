# Duskey

Каталог цифровых товаров (аффилиат-витрина на GGSel) + собственный модуль
пополнения Steam с реальной оплатой через **Antilopay API**.

## Структура проекта

```
api/index.js          — точка входа для Vercel (экспортирует Express-приложение)
app.js                 — само Express-приложение (роуты, статика)
server.js              — запуск локального сервера (node server.js)
lib/antilopay.js        — подпись/проверка запросов и клиент Antilopay API
lib/store.js            — хранилище заказов (Upstash Redis в проде, /tmp локально)
routes/steamTopup.js     — проверка Steam-аккаунта, создание пополнения, статус
routes/antilopayWebhook.js — приём и проверка подписи Callback от Antilopay
public/index.html        — витрина (бывший catalog-v12.html), раздаётся как статика
```

## Как это работает

- Каталог (`public/index.html`) — статичная витрина. Все карточки, кроме
  «Пополнение Steam», ведут на GGSel по партнёрской ссылке, как и раньше.
- Виджет «Пополнение Steam» теперь **не** уходит на сторону — он вызывает
  `POST /steam/check-account`, потом `POST /steam/create` на этом же сервере,
  которые обращаются к Antilopay API (`lib/antilopay.js`), создают платёж и
  возвращают `payment_url`, куда пользователь и переадресуется.
- После оплаты Antilopay шлёт Callback на `POST /antilopay-webhook` —
  подпись проверяется публичным ключом (`ANTILOPAY_PUBLIC_KEY`), статус
  заказа обновляется в хранилище.
- Страницы `GET /steam/success` и `GET /steam/fail` — куда Antilopay
  редиректит пользователя после оплаты.

## Локальный запуск

```bash
npm install
cp .env.example .env      # заполните ключи (см. ниже)
npm run dev                # http://localhost:3000
```

Без реальных `ANTILOPAY_*` ключей сайт откроется и будет работать, но
кнопка «Купить» в виджете Steam вернёт ошибку — это ожидаемо.

## Деплой на Vercel

1. Залейте проект в git-репозиторий, импортируйте его в Vercel
   (vercel.com → Add New → Project).
2. Vercel сам подхватит `vercel.json` — весь трафик идёт в
   `api/index.js`, где живёт Express-приложение целиком (статика,
   API, вебхук).
3. В Project Settings → Environment Variables добавьте все переменные из
   `.env.example`, как минимум:
   - `SITE_URL` — итоговый домен проекта (важно для `success_url`/`fail_url`)
   - `ANTILOPAY_PROJECT_ID`, `ANTILOPAY_SECRET_ID`, `ANTILOPAY_PRIVATE_KEY`,
     `ANTILOPAY_PUBLIC_KEY` — из личного кабинета Antilopay
4. **Хранилище заказов.** На Vercel нет постоянной файловой системы — без
   внешнего хранилища заказы будут теряться между вызовами функции.
   Подключите Redis: Project → Storage → Marketplace Database Providers →
   **Redis** (Upstash) → Connect. Vercel сам пропишет переменные вида
   `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` (или старые
   `KV_REST_API_URL`/`TOKEN`, если у вас уже был подключён Vercel KV раньше
   — `lib/store.js` понимает оба варианта). Без этого шага проект всё
   равно задеплоится и заработает, но проверка статуса заказа
   (`GET /steam/status/:order_id`) не будет надёжной.
5. Задеплойте (`git push` или кнопка Deploy).
6. В личном кабинете Antilopay, в настройках вашего Проекта, укажите адрес
   приёма Callback: `https://<ваш-домен>/antilopay-webhook`.
7. Проверьте `https://<ваш-домен>/health` — должно вернуть
   `"storage":"upstash-redis"` (если Redis подключён) и открыться сама
   витрина на `/`.

## ⚠️ Юридические тексты — обязательно проверьте перед публикацией

В `public/index.html` есть три юридических документа (публичная оферта,
политика конфиденциальности, возврат и обмен), которые изначально были
написаны для сайта-каталога, **не принимающего оплату вообще** («Duskey не
принимает оплату… всё это пользователь указывает на стороне GGSel»). Я
добавил в них разделы-исключения для нового раздела «Пополнение Steam»
(где деньги и данные — логин Steam, email — реально обрабатываются этим
сайтом через Antilopay), но это черновая правка, а не готовый юридический
текст:

- в оферте, п. 2.1 стоит `[TODO: заменить на реальные реквизиты продавца]`
  — нужно вписать реальные данные продавца услуги пополнения (ИП/самозанятый/ООО);
- стоит свериться с требованиями 152-ФЗ по обработке персональных данных
  (email, IP) и, при необходимости, с юристом — особенно если планируете
  принимать банковские карты.

До этой правки видимая пользователю политика конфиденциальности прямо
утверждала, что сайт не собирает email и логины — с реальной оплатой
через Antilopay это уже не так, и стоило поправить, прежде чем пускать
на сайт живой трафик и деньги.

## Полезные эндпоинты

| Метод | Путь                          | Назначение                                  |
|-------|-------------------------------|----------------------------------------------|
| GET   | `/health`                     | статус сервиса и хранилища                    |
| POST  | `/steam/check-account`        | проверка Steam-логина                         |
| POST  | `/steam/create`                | создание платежа на пополнение                |
| GET   | `/steam/status/:order_id`      | статус заказа (для поллинга)                  |
| POST  | `/antilopay-webhook`           | приём Callback от Antilopay                   |
| GET   | `/steam/success` / `/steam/fail` | редирект-страницы после оплаты              |
| GET   | `/pet/:ownerId`                | статы питомца (тамагочи)                      |
| POST  | `/pet/:ownerId`                | завести питомца                               |
| POST  | `/pet/:ownerId/action`         | покормить / играть / спать / разбудить        |

## Тамагочи (бонусный питомец)

Внизу страницы — котёнок/щенок, которого можно кормить, укладывать спать
и с которым можно играть (см. `.tama-section` в `public/index.html`).
Задумано как задел под донат в будущем — сейчас монетизации никакой нет,
просто бонус для пользователей бота.

Хранится в Supabase (таблица `tamagotchi_pets`), но **сайт полностью
работает и без неё**: если Supabase не подключён, фронтенд сам молча
переключается на `localStorage` (см. `TamaStore` в `public/index.html`) —
питомец просто не будет синхронизироваться между устройствами, пока база
не настроена.

Чтобы включить синхронизацию через Supabase:

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного
   тарифа для этого с головой хватит).
2. В SQL Editor выполните `supabase/schema.sql` — создаёт таблицу
   `tamagotchi_pets`.
3. В Project Settings → API скопируйте **Project URL** и
   **service_role key** (не anon — пишем в базу только с сервера).
4. Добавьте в переменные окружения (Vercel → Settings → Environment
   Variables, или `.env` локально):
   ```
   SUPABASE_URL=https://xxxxx.supabase.co
   SUPABASE_SERVICE_ROLE_KEY=eyJ...
   ```
5. `npm install` (подтягивает `@supabase/supabase-js`) и передеплойте.

Формулы голода/бодрости/радости и действия (покормить/играть/спать)
продублированы в `routes/tamagotchi.js` (сервер) и в `public/index.html`
(офлайн-режим) — это осознанно: клиент должен вести себя так же и без
сервера. Меняете баланс — меняйте в обоих местах (в коде есть
комментарии-указатели друг на друга).

Идентификация питомца: в Telegram — по `tg.initDataUnsafe.user.id`, на
обычном сайте — по случайному id в `localStorage`. Аккаунтов/логина нет —
это просто бонус, не хотелось городить регистрацию ради котика.

### Прогресс, магазин и ежедневный стрик

Поверх базового кормления/игры/сна добавлен игровой цикл, рассчитанный на
привычку заходить каждый день:

- **Опыт и уровни** — кормление, игра и ежедневная награда дают опыт; при
  наборе нужного количества питомец левелапится (анимация + конфетти +
  бонус монет). Формула — `xpToLevel(level)` в `routes/tamagotchi.js`
  (продублирована в `public/index.html`).
- **Монеты** — игровая валюта, начисляется понемногу за уход (кормление,
  игру, честный сон) и тратится в магазине. Стартовый баланс — 20.
- **Кормление — только из инвентаря.** Питомец больше не ест «из ниоткуда»:
  чтобы покормить, нужна купленная в магазине еда. При создании питомец
  получает стартовый набор (3× «Крошки»), дальше еду докупают на монеты.
  Нажатие «Кормить» открывает список своей еды с остатками; если еды нет —
  сразу переносит в магазин с подсказкой.
- **Магазин** (вкладка «Магазин» в панели питомца), четыре раздела:
  - *Еда* — 7 уровней от дешёвых «Крошек» (4🪙) до «Деликатеса шефа» (75🪙,
    открывается с 8 уровня): чем дороже, тем сильнее насыщает и больше
    опыта/монет даёт за кормление.
  - *Игрушки* — 4 уровня от «Мячика» (10🪙) до «Лазер-игрушки» (40🪙,
    открывается с 6 уровня): дают больше радости/опыта, чем обычная игра
    без игрушки (та тоже доступна всегда бесплатно, просто скромнее).
  - *Аксессуары* — бантик/очки/кепка/шарф/корона, надеваются поверх питомца.
  - *Фоны* — луг/закат/ночь/космос, меняют задник сцены.
  Еда и игрушки покупаются стопкой (можно закупиться впрок), аксессуары и
  фоны — разовая покупка с переключением «надеть/снять». Каталог и цены —
  `TAMA_SHOP_CATALOG` в `public/index.html` / `SHOP_CATALOG` в
  `routes/tamagotchi.js`.
- **Ежедневная награда и стрик** — раз в сутки (по UTC-дате) можно забрать
  бонус монет и опыта; баннер с анимацией пульсации и точка-«напоминалка»
  на плавающей кнопке сами подсвечивают, что награда ждёт. Стрик растёт,
  если заходить без пропусков день в день, и даёт бонус каждую 7-ю сессию.
  Логика — `applyDailyClaim` в обоих файлах.

Все новые поля (`level`, `xp`, `coins`, `streak`, `last_daily_claim`,
`inventory`, `equipped_accessory`, `equipped_background`, `food`, `toys`)
добавлены в `supabase/schema.sql` через `alter table ... add column if
not exists`, так что накатывается безопасно поверх уже существующей
таблицы — старые питомцы просто получат значения по умолчанию при первом
обращении (см. `ensureFields`/`tamaEnsureFields`).

### Обновление: хвост, глажка свайпом, звук, фикс инвентаря

- **Инвентарь при кормлении/игре чинён.** Список раньше строился по
  каталогу магазина и фильтровался по остаткам — если предмет по
  какой-то причине не совпадал с текущим каталогом, он молча пропадал
  из списка кормления, хотя количество в данных оставалось. Теперь
  список строится напрямую по `pet.food`/`pet.toys` (`tamaItemPickerRowsHtml`),
  каталог используется только для названия/эмодзи, а для неизвестных id
  есть нейтральная заглушка вместо исчезновения (`TAMA_FALLBACK_FOOD`/`TOY`
  и в `public/index.html`, и в `routes/tamagotchi.js`).
- **Хвост** у кота и у собаки — свой силуэт под каждого (`.pet-tail` в
  `tamaPetSvg`), с CSS-анимацией виляния: медленно в покое, быстро и широко
  в happy/игре/кормлении/глажке, опущен в sad, замирает во сне.
- **Глажка свайпом** — новое действие `pet` (сервер + офлайн-клиент),
  привязанное к жесту (pointerdown/move/up на спрайте питомца), а не к
  клику: во время движения пальца/мыши сыплются сердечки и мордочка
  довольная, а реальная награда (радость +6, опыт +2) и сетевой вызов
  ограничены `TAMA_PET_CALL_GAP_MS` (4с) на клиенте и `PET_COOLDOWN_MS`
  (15с) на сервере, чтобы жест не фармился в бесконечный опыт. Новое поле
  `last_pet_at` добавлено в схему тем же безопасным `alter table`.
- **Звук** — короткие сигналы на кормление/игру/глажку/сон/пробуждение/
  покупку/левелап через `TamaSound` (`public/index.html`): осцилляторы
  Web Audio API, синтезированные на лету. Важно: это не запись живого
  звука — в среде разработки нет микрофона/студии, поэтому вместо
  сэмплов-файлов это программно сгенерированные чиптюн-сигналы; unlock
  отдельно не нужен, т.к. вызываются прямо из обработчиков клика/жеста.

### Обновление: визуальная полировка, анти-фарм и «товар дня»

- **Потребности сами снижаются со временем** — это уже было (`applyTamaDecay`
  на основе `HUNGER_PER_MIN`/`ENERGY_AWAKE_PER_MIN`/`HAPPY_PER_MIN`), но
  теперь это ещё и видно на глазах: живой пересчёт раз в 30с (было 60с) и
  дополнительный пересчёт сразу при открытии панели питомца
  (`tamaOpenPanel`).
- **Анти-фарм опыта/еды.** Раньше можно было кормить/играть бесконечно,
  даже если питомец уже сыт/весел — фармя опыт и монеты в цикле. Теперь
  действие блокируется без траты еды/игрушки и без опыта, если:
  - голод уже закрыт (`hunger <= HUNGER_FULL_MAX`, т.е. `≤8`) — кормить
    нельзя;
  - радость и так почти на максимуме (`happiness >= HAPPY_PLAY_MAX`,
    `≥92`) — играть нельзя;
  - бодрости и так почти максимум (`energy >= ENERGY_AWAKE_MAX`, `≥95`) —
    спать не даёт.
  Пороги и сама проверка продублированы в `routes/tamagotchi.js` и
  `public/index.html`, как и остальная игровая логика.
- **«Мысли» питомца.** Заблокированное действие теперь не просто пишет
  текст под питомцем — над головой всплывает настоящий пузырь-мысль
  («Я не хочу есть — я сыт!», «Не хочу играть — мне и так весело!» и т.д.,
  `.tama-thought`/`tamaShowThought`). Плюс фоновые напоминания-мысли, когда
  голод/грусть/усталость впервые пересекают критический порог
  (`tamaCheckAmbientThought`) — срабатывают один раз на пересечение, а не
  каждую минуту, чтобы не спамить.
- **Звук — добавлены недостающие сигналы**: отказ в действии (`denied`),
  надевание аксессуара (`equip`), получение ежедневной награды (`claim`) —
  раньше эти моменты были беззвучными. Глажка теперь ещё и **подкидывает
  питомца** (`tamaPetHop`) вместо лёгкого подрагивания — свайп ощущается
  как настоящий восторг, а не дрожь.
- **Аксессуары реально «едут» на питомце**, а не висят статичной картинкой:
  у каждого предмета своя лёгкая анимация покоя (покачивание), плюс тот же
  hop/jump, что и у самого питомца, при глажке/игре — синхронизировано по
  длительности и итерациям. У бантика вдобавок отдельное положение для
  собаки (у неё нет кошачьего острого уха, поэтому крепится иначе,
  `.species-dog .tama-accessory-bow`).
- **Фоны — многослойные, не плоская заливка**: луг с холмом и травой,
  закат со светящимся солнцем, ночь/космос с мерцающими звёздами (и луной
  / планетой соответственно) — чистый CSS, без картинок-ассетов. Магазинные
  карточки фонов не поменялись, поменялась только сама отрисовка сцены
  (`.tama-stage[data-bg="..."]`).
- **Новая механика магазина: «товар дня».** Раз в сутки один случайный
  предмет каталога продаётся со скидкой 30% — баннер над магазином
  показывает, что именно, бейдж «🔥 −30%» и зачёркнутая старая цена — на
  карточке. Выбор детерминирован UTC-датой и порядком ключей каталога
  (`tamaDailyDealId`/`dailyDealId`), поэтому сервер и офлайн-режим всегда
  сходятся на одном и том же товаре без обмена данными — ничего
  дополнительно не хранится в БД, схему менять не пришлось.
- **Редкость товаров** (common/rare/epic/legendary) — чисто визуальная
  метка в магазине (цветная рамка + подпись у некоторых карточек), задел
  на будущую прокачку; на баланс/цены не влияет, поэтому специально не
  дублируется на сервере (аналогично `TAMA_PALETTE`).


### Обновление 2: реальные звуки, аксессуары «на теле», починка бага сна+глажки

Важная оговорка про звук сразу: в этой среде нет доступа к библиотекам
живых сэмплов/аудио-CDN (сеть для инструментов ограничена только реестрами
пакетов npm/pip/crates), поэтому «настоящую запись мурчания кота» скачать
и подключить невозможно технически. Вместо этого звуки — более честная
процедурная синтеза через Web Audio API (`TamaSound` в `public/index.html`):
шумовые буферы через биквадратные фильтры вместо чистых осцилляторов там,
где это ближе к реальному звуку.

- **Мурчание при глажке.** Новые `TamaSound.purrStart(species)` /
  `purrStop()` — включаются на `pointerdown` и выключаются при отпускании
  пальца/мыши, длятся всё время свайпа (не одноразовый сигнал). Кот:
  синусоида ~85 Гц с амплитудной модуляцией ~27 Гц (частота, близкая к
  реальному кошачьему мурлыканью). Собака не мурчит физиологически —
  вместо этого мягкое довольное пыхтение (отфильтрованный шум с редкой
  модуляцией «вдохов»).
- **Хруст еды** (`TamaSound.feed`) — три коротких шумовых «щелчка» через
  bandpass-фильтр вместо предыдущих чистых тонов, плюс тихое «ням» в конце.
- **Дыхание во сне** (`TamaSound.sleep`) — два мягких «вдоха-выдоха» через
  низкочастотный шум вместо нисходящих синусоид.
- **Аксессуары — теперь буквально часть SVG питомца**, а не отдельная
  HTML-картинка поверх. Раньше позиционирование процентами от контейнера
  систематически не совпадало с реальными частями тела и не двигалось
  вместе со спрайтом. Теперь координаты сняты напрямую с самой иллюстрации
  (глаза/уши/шея — `TAMA_ACC_POS`/`tamaAccessorySnippet` в
  `public/index.html`): очки — два круга ровно поверх нарисованных глаз с
  дужками, шарф — векторная лента с узлом на шее, бантик/кепка/корона —
  эмодзи, встроенные в SVG-координаты головы (свои для кота и для собаки —
  у собаки нет острых кошачьих ушей). Поскольку это теперь реально дети
  `<svg class="tama-pet-svg">`, они бесплатно наследуют анимации самого
  спрайта (hop при глажке, дыхание во сне) — отдельно синхронизировать
  эмодзи-слой больше не нужно, вся прошлая keyframe-эквилибристика под это
  удалена.
- **Починен баг «двойного рта».** Если погладить спящего питомца, класс
  `.mood-pet-touch` (улыбающийся рот) раньше накладывался поверх
  `.mood-sleep` (сонный рот) — оба были видны одновременно. Теперь для сна
  отдельный класс `sleep-purr`: лицо остаётся сонным (закрытые глаза +
  сонный рот), тело слегка подрагивает — как будто мурлычет во сне, без
  конфликта классов.
- **Потребности снижаются быстрее** — голод/бодрость/радость теперь падают
  примерно в 2 раза быстрее (`HUNGER_PER_MIN`/`ENERGY_AWAKE_PER_MIN`/
  `HAPPY_PER_MIN` в `routes/tamagotchi.js` и `public/index.html`): было
  почти незаметно за обычную сессию, теперь движение полосок видно и в
  моменте, и за день только усиливается — но не настолько быстро, чтобы
  требовать заходить каждый час.

### Обновление: аксессуары/звук/мысль/анимация пикера

- **Аксессуары теперь физические SVG-фигуры, а не эмодзи.** Бантик, кепка,
  корона, веночек и монокль раньше рисовались через `<text>` с эмодзи —
  выглядело как наклейка поверх шерсти. Теперь это векторные фигуры
  (`tamaAccessorySnippet` в `public/index.html`), нарисованные напрямую в
  координатах тела питомца — сидят на месте (на макушке/ушах/переносице), а
  не парят отдельно. Очки и шарф так уже было сделано раньше — сейчас
  дотянут монокль по тому же принципу (одна линза + цепочка на правом глазу).
- **"Мысль" питомца — исправлен нечитаемый белый текст.** Пузырь мысли был
  жёстко на `background:#fff`, а цвет текста брался из темы
  (`var(--ink)`) — в тёмной теме `--ink` светлый, получалось светлым по
  светлому, то есть не видно. Теперь и фон, и текст берутся из темы
  (`var(--surface)`/`var(--ink)`) — всегда контрастная пара при любой
  теме. Заодно пузырь сдвинут сбоку от головы (было по центру над ней).
- **Открытие "Кормить"/"Играть" стало плавным.** Список еды/игрушек раньше
  переключался через атрибут `hidden` — мгновенный скачок без анимации,
  ощущался как рывок/лаг. Теперь плавно раскрывается по высоте/прозрачности
  (класс `.is-open` вместо `hidden`, CSS-transition на `max-height`).
- **Звук перезаписан на более мягкий.** Резкие `square`-осцилляторы (play/
  buy) заменены на `triangle` с мягкими интервалами; добавлена общая шина
  с lowpass-фильтром и лёгким "хором" (два слегка расстроенных голоса) —
  вместо плоского "писка" получается более округлый, приятный перезвон.
  Хруст еды/дыхание во сне/мурчание остались на прежней (уже неплохой)
  шумовой основе — их не трогали.

### Обновление: мурчание/сон/хруст переделаны, глажка и инвентарь починены

- **Мурчание кота и "пыхтение" собаки переделаны с нуля.** Было: чистый
  осциллятор (85 Гц) с амплитудной модуляцией — на телефонных динамиках
  звучит как гудение будильника, а не мурлыканье (справедливая жалоба).
  Стало: сама фактура на отфильтрованном шуме (мурлыканье физически и есть
  шумовая вибрация, не чистый тон) с мягким lowpass — никакого "жужжания".
  У собаки — вместо сплошного шумового гула теперь короткие ритмичные
  "выдохи" через паузы, похоже на довольное дыхание, а не на статику.
- **Звук сна переделан на тихую колыбельную.** Было шумовое "дыхание"
  (звучало резко/скрежеще). Стало — три мягких нисходящих тона без единого
  шумового элемента, гораздо спокойнее.
- **Хруст еды чуть доработан** — центр фильтра ниже (более "мясистый"
  хруст) и вместо одной ноты в конце — тёплое двухнотное "ням-ням".
- **Глажка иногда "не срабатывала с первого раза" — нашли причину.**
  Действие засчитывалось только если палец сдвигался больше чем на 6px;
  лёгкое короткое касание/погладить без явного свайпа не регистрировалось
  вообще, из-за чего казалось, что "надо гладить дважды". Теперь
  засчитывается любое отпускание пальца на питомце (сердечки и звук —
  тоже сразу, без требования сдвига).
- **Список кормления/игрушек иногда "сам захлопывался" — нашли причину.**
  Открыт/закрыт список раньше жил только в CSS-классе `.is-open` на DOM-
  узле; любое действие (и тихий пересчёт статов раз в 60 секунд) вызывает
  полную пересборку разметки (`renderTamagotchi`), а свежая разметка всегда
  была закрыта — если пересчёт срабатывал ровно в момент, когда список был
  открыт, он молча захлопывался. Теперь открыт/закрыт хранится в
  переменной (`tamaFoodPickerOpen`/`tamaToyPickerOpen`) и подставляется в
  разметку при каждой пересборке, так что случайный фоновый рендер больше
  не сбрасывает состояние.

- **Важно, сразу скажу как есть:** сгенерировать фоны настоящей нейронкой

  был раньше.
- **Луг убран из магазина совсем** — как и просили, локация действительно
  не вписывалась. Если у кого-то он уже куплен/надет — просто перестанет
  подсвечиваться на сцене (не ошибка, а следствие удаления из каталога).
- **Добавлен новый топовый фон "Сияние"** (полярное сияние: несколько
  волнистых цветных лент по тёмному небу + горный силуэт + звёзды) —
  требует 7 уровень, самый красивый и самый дорогой.
- **Прогрессия фонов и части аксессуаров теперь по уровням:** закат — без

- **В карточке магазина у фона теперь мини-превью реального арта**
  (упрощённая, но узнаваемая версия), а не голая эмодзи-иконка — сразу
  видно, что покупаешь, не открывая по факту покупки.
- **Сетка магазина сделана устойчивее к переполнению.** Раньше колонки
  задавались как `1fr 1fr` — если название/цена не помещались, трек мог

### Обновление: бейдж редкости фона в магазине снова виден

- **Причина нашлась в порядке отрисовки, не в размере превью.** Бейдж
  редкости и предпросмотр фона оба `position: absolute`/`relative` без
  z-index — по умолчанию такие слои рисуются в порядке, в котором стоят в
  разметке, а предпросмотр в HTML идёт ПОСЛЕ бейджа, поэтому просто
  перекрывал его сверху, независимо от размера. Задал бейджам явный
  `z-index: 2` — теперь они всегда поверх превью. Заодно добавил
  золотое свечение вокруг превью для легендарного фона (раньше свечение
  было только на эмодзи-иконке, у превью фона его не было).

### Обновление: проверка баланса монет + анимации кормления/радости

- **Да, экономика реально была сломана — спасибо, что попросили
  проверить.** Посчитал по факту (не на глаз): при текущих на тот момент
  скоростях распада (голод — 1 очко/4 мин, радость — 1 очко/8 мин) и
  кулдауне поглаживания в 24 часа расход монет на поддержание радости
  одними игрушками выходил ~135 монет/день, плюс голод ~70-90 монет/день —
  итого 200+ монет/день трат против ~25-30 монет/день дохода с ежедневного
  бонуса. Это гарантированный уход в минус, а поглаживание (раньше
  бесплатный и частый источник радости) в какой-то момент срезали до раза
  в сутки, чтобы не фармили — но заодно убрали единственный бесплатный
  клапан для радости.
  - Голод вернул к прежней (более медленной) скорости — жалобу "не видно
    прогресса за сессию" теперь решает более частое обновление полосок на
    экране (раз в 30с — уже было сделано), а не двукратное ускорение
    самого распада.
  - Радость ослабил больше остальных (была главной причиной перекоса).
  - Поглаживание — снова частый бесплатный источник радости (кулдаун
    награды 3 минуты вместо 24 часов), а не разовая награда раз в сутки:
    вовлечённый игрок теперь покрывает бóльшую часть радости просто
    взаимодействием, не тратя монеты на игрушки.
  - Вернул прокачку, дающую реальную скидку на голод/усталость/скуку с
    уровнем (была в одной из версий, потерялась при правках) — до 35%
    медленнее к 8 уровню, видно рядом с уровнем в шапке (🌟 −X%).
  - Стартовый баланс 20 → 40 монет, дневной бонус чуть выше (база 10 → 14),
    самая дешёвая еда/игрушка дают чуть больше монет за использование.
  - После всех правок прикидочный расход на голод у игрока 1 уровня — в
    районе дневного дохода (не в разы больше), а не гарантированный минус;
    дальше становится легче за счёт прокачки.
- **Кормление теперь видно как кормление.** Раньше эмодзи еды просто
  улетал вверх и таял, как любой другой эффект — не читалось как "именно
  скормили". Теперь еда стартует снизу, едет ко рту и там уменьшается до
  нуля (проглочено) — новая анимация `tamaEatFx`/`tamaEatTravel`, отдельная
  от обычного fx. Плюс показывается эмодзи именно того корма, которым
  покормили (рыбка, торт и т.д.), а не универсальная кость.
- **Питомец радуется по-разному — и еде/игрушке получше, и каждой новой
  вещи в магазине.** Редкий/эпический/легендарный корм или игрушка при
  использовании дают дополнительные искорки и чуть более долгую радостную
  мордочку (`happyExtraMs` в `tamaDoAction`). А для аксессуаров/фонов —
  они уникальны, повторно купить нельзя, так что каждая успешная покупка
  и есть "впервые" — реакция масштабируется по редкости
  (`tamaCelebrateNewItem`): обычная вещь — искорка и мордочка радости,
  редкая — искорки + сердечки, эпическая — конфетти на весь экран,
  легендарная — двойной залп конфетти + звук уровня + отдельный тост.
  Работает даже если покупка происходит на вкладке "Магазин" (там нет
  спрайта питомца) — реакция построена на конфетти уровня всей страницы,
  а не на эффектах поверх питомца, которых там физически нет.

### Обновление: стартовый баланс срезан — за косметику снова нужно "идти"

- **Проблема прошлого шага:** поднял стартовые монеты 20 → 40, чтобы
  снять угрозу ухода в минус на еде — но заодно новый игрок мог сразу в
  первую минуту купить бантик (15) + шарф (18) почти на старте, без
  какого-либо прогресса. Это убивало ощущение "надо накопить/дорасти".
- **Правка:** стартовый баланс 40 → 12 — меньше цены самого дешёвого
  аксессуара (бантик, 15), так что в день 1 купить косметику физически
  нельзя, зато на еду хватает (плюс 3 бесплатные крошки в стартовом
  инвентаре). Ежедневный бонус и скидки на еду от прошлого шага не
  трогал — они отвечают за не-уход-в-минус на пропитании, это отдельная
  задача от "не давать сразу всё скупить", и трогать её не нужно было.
- Ценовая лестница косметики (уже была выстроена в предыдущих правках)
  осталась как есть — она и так требует роста уровня и/или нескольких
  дней дохода: бантик/шарф без требования по уровню — первая цель на
  день-два, очки/кепка требуют 2-3 уровень, корона (60) и топовый фон
  "Сияние" (70, ур.7) — по-настоящему долгие цели.
